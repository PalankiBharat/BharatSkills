# Phase 2: GitHub Issue Creation

## Setup

```bash
REPO=$(jq -r '.repo' ~/.skill-feedback-config.json)
SESSION_DATE=$(date +%Y-%m-%d)
```

## Which skills get issues?

| Rating | Friction/Gaps reported? | Action |
|--------|------------------------|--------|
| ⭐-⭐⭐ | Any | Create issue (P0) |
| ⭐⭐⭐ | Yes | Create issue (P1) |
| ⭐⭐⭐ | No ("it was okay") | Skip — too vague |
| ⭐⭐⭐⭐ | Yes | Create issue (P1 or P2) |
| ⭐⭐⭐⭐ | No | Skip |
| ⭐⭐⭐⭐⭐ | No | Skip |
| N/A (trigger failure) | — | Create issue (P0) |

**Every issue should be worth reading and acting on.**

## Check for duplicates before creating

### Step 1: Check open issues

```bash
gh issue list -R "$REPO" --label "skill:<skill-name>" --state open \
  --json number,title,labels,body --limit 20
```

If a matching open issue exists (same friction or capability gap):
- **Add a comment** instead of creating a duplicate:

```bash
gh issue comment <NUMBER> -R "$REPO" --body "## Session Update: $SESSION_DATE

**Rating this session:** <stars> (<N>/5)
**Invocations:** <count>

Still experiencing this issue. Additional context:
- <new observation from this session>

_Recurring issue across multiple sessions. Consider priority escalation._"
```

### Step 2: If no open match, check closed issues

```bash
gh issue list -R "$REPO" --label "skill:<skill-name>" --state closed \
  --json number,title,labels,body --limit 20
```

If a matching closed issue exists (same friction or capability gap):
- **Reopen the issue** — a recurrence means the fix didn't hold:

```bash
gh issue reopen <NUMBER> -R "$REPO"
gh issue edit <NUMBER> -R "$REPO" --add-label "session:$SESSION_DATE"
gh issue comment <NUMBER> -R "$REPO" --body "## Reopened — Recurrence on $SESSION_DATE

**Rating this session:** <stars> (<N>/5)
**Invocations:** <count>

This issue recurred after being closed. Context:
- <new observation from this session>

_Reopened automatically by skill-feedback. Previous fix did not resolve the underlying issue._"
```

### Step 3: If no match at all, create a new issue

## Issue creation

### Labels

Every issue gets:
- `skill:<skill-name>` — e.g., `skill:feature-analyzer`
- `priority:<P0|P1|P2>` — based on classification rules below
- `session:<YYYY-MM-DD>` — e.g., `session:2026-03-20`

Plus one or more type labels:
- `type:friction` — workflow friction
- `type:output-quality` — wrong or incomplete output
- `type:missing-capability` — feature request
- `type:triggering` — skill didn't trigger or triggered incorrectly

Dynamically create `skill:*` and `session:*` labels if they don't exist:

```bash
gh label create "skill:<name>" -R "$REPO" --color "C5DEF5" --description "Skill: <name>" 2>/dev/null || true
gh label create "session:$SESSION_DATE" -R "$REPO" --color "D4C5F9" --description "Session: $SESSION_DATE" 2>/dev/null || true
```

### Priority classification

- **P0 — Fix immediately:** Triggering failures, incorrect output needing manual correction, blocking friction. Any skill rated ⭐ or ⭐⭐.
- **P1 — Fix this week:** Missing capabilities in 2+ sessions (check past issues), recurring friction, skills rated ⭐⭐⭐ with actionable improvements.
- **P2 — Backlog:** Nice-to-haves, first-time minor friction. Skills rated ⭐⭐⭐⭐ with minor suggestions.

### Issue title format

```
[skill-feedback] <skill-name>: <concise problem summary>
```

Examples:
- `[skill-feedback] feature-analyzer: Domain analysis misses F&O regulatory edge cases`
- `[skill-feedback] jetpack-compose: Failed to trigger on "create a Compose screen"`
- `[skill-feedback] qa-autopilot: Test generation skips ViewModel unit tests`

### Issue body

```bash
gh issue create -R "$REPO" \
  --title "[skill-feedback] <skill-name>: <summary>" \
  --label "skill:<skill-name>,priority:<P>,type:<type>,session:$SESSION_DATE" \
  --body "## Skill Feedback: <skill-name>

**Session date:** $SESSION_DATE
**Project:** <project name>
**Invocations:** <count>
**Rating:** <stars> (<N>/5)

---

### What worked
- <strength 1>
- <strength 2>

### Friction points
- **<Symptom>** — <Root cause hypothesis>. Likely in \`<SKILL.md section or reference file>\`.

### Suggested SKILL.md improvements
- **Section:** \`<file or section>\`
  **Current:** <what happens>
  **Suggested:** <what should change>
  **Rationale:** <why>

### Missing capabilities
- **<Capability>** — <Description>. Complexity: \`<Quick win | Medium | Large>\`

### Triggering issues
_(only if applicable)_
- **Phrase used:** \"<what the developer said>\"
  **Expected:** trigger \`<skill>\`
  **Actual:** <what happened>
  **Suggested description update:** \"<wording to add>\"

### Trend analysis
<generated by reading references/trend-analyzer.md>

---
**Priority:** \`<P0 | P1 | P2>\`
_Generated by skill-feedback_"
```
