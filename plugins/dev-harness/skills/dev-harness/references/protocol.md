# Protocol — mailboxes, statuses, sentinels

Every run owns a `.harness/` directory at the repo root (gitignored). The Orchestrator and the panes communicate ONLY through files in it. **Only the Orchestrator writes a role's inbox**; a pane reads only its own inbox. Pane isolation is structural.

## Layout
```
.harness/
  story.md · log.md · state.json · .stop-watchdog (on completion) · watchdog.log
  send · poll · ask · answer · require · run · resume · done   (path-independent wrappers)
  orchestrator/   inbox.md worklog.md pane
  tech-lead/ dev/ qa/ architect/   each: inbox.md outbox.md status feedback.md worklog.md activity.log session pane
  qa/emulator.lock
  artifacts/  spec.md feature-analysis.md findings.md open-questions.md questions.json
              tech-plan.md design.md plan.md dev-handoff.md
              qa-scenarios.md qa-flows/ qa-report.md architect-review.md architect-replan.md testtag-requests.md
  review/     themed HTML review pages
```

## Status sentinel (`<role>/status`)
| status | meaning |
|---|---|
| `idle` | waiting |
| `working` | the Orchestrator wrote a new inbox + nudged; the pane is processing (only the Orchestrator sets this) |
| `done` | finished; the agent ran `bash .harness/done <role>` after writing its artifacts |
| `blocked` | cannot proceed (emulator died, missing input, out of runway) |

## Liveness (file-based — no screen-scraping)
A `working` role is "alive" if any of these mtimes is recent: its `worklog.md` (per-step heartbeat the agent appends), its `activity.log` (a long build/test tee'd via `.harness/run`), or its Claude transcript (found via the `session` id it records — advances during pure thinking). The watchdog wakes a never-woke role once, stays quiet while it progresses, and on sustained silence sends one check-in then ESCALATEs to the user. See `agents/orchestrator.md`.

## Artifact paths (canonical)
All scratch artifacts live under `.harness/artifacts/` (gitignored). A worker's cwd is the **repo root**, so always use the full `.harness/artifacts/<file>` path — never bare `artifacts/<file>`. Code goes to `app/src/**` (or the `:lib` modules the design names). The Orchestrator verifies the `EXPECT:`ed artifact with `.harness/require` before advancing.

## Dispatch contract
An inbox message is `<INSTRUCTION>` + optional `EXPECT: <artifact path>`. The agent signals `bash .harness/done <role>` (or `… blocked`) as its **last** action. The Orchestrator then verifies the EXPECTed artifact exists/non-empty — `done` with a missing artifact = treat as `blocked`.

## Helper scripts (`scripts/`)
`lib.sh` · `harness-init.sh` · `send.sh` · `poll.sh` (`--settle`) · `ask`/`render-questions.sh` · `answer`→`send.sh` · `require` · `run` (activity tee) · `watchdog.sh` · `harness-resume.sh` · `agent-pane.sh` · `harness-allow.sh` · `feedback.sh` · `render-review.sh`. The `.harness/<name>` wrappers are generated by `harness-init.sh` with `HARNESS_ROOT` baked in.
